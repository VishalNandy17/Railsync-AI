# RailSync AI — local demo dashboard

Shows the XGBoost criticality model's results on held-out test data, SHAP
explanations per task, and the OR-Tools CP-SAT schedule, in a browser at
`http://localhost:8000`.

Everything here is a demo running on the **synthetic** SIH26027 dataset —
not Indian Railways data, not a production system.

## Structure

```
backend/
  data/                       synthetic CSVs
  train_and_export.py         trains the model, runs the scheduler, saves artifacts
  main.py                     FastAPI app — serves the API + the frontend
  requirements.txt
  artifacts/                  generated by train_and_export.py (git-ignore this)
frontend/
  index.html, styles.css, app.js     plain HTML/JS dashboard (no build step needed)
```

## Run it

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

python3 train_and_export.py     # trains the model + scheduler, ~1-3 min, writes ./artifacts

uvicorn main:app --reload --port 8000
```

Then open **http://localhost:8000** in a browser. That's it — `main.py`
serves both the API (under `/api/...`) and the static dashboard files from
the same origin, so there's no separate frontend server or CORS setup
needed.

## What you'll see

- **Overview** — overall test MAE/R², train-vs-test gap (overfitting check),
  per-priority-class MAE, a baseline comparison table (Linear Regression /
  Random Forest / XGBoost), an actual-vs-predicted scatter chart, and the
  global SHAP feature-importance chart.
- **Predictions** — every held-out test-set task with actual vs. predicted
  criticality. Search/filter it, click a row, and the right-hand panel
  fetches a live SHAP explanation for that specific task (which features
  pushed its score up or down).
- **Schedule** — the OR-Tools CP-SAT result on the 250-row demo subset:
  which tasks got a day assigned within the 14-day horizon under the
  corridor block-time, crew-capacity, and permit-readiness constraints, and
  which were left in the backlog because capacity ran out.

## Re-running after a change

If you edit `train_and_export.py` (e.g. to change the corridor/crew
capacity assumptions, the planning horizon, or retrain on updated data),
just re-run it — it overwrites everything in `artifacts/` — then restart
`uvicorn` (or let `--reload` pick it up).

## Notes / known limitations

- `/api/explain/{task_id}` computes SHAP live per request (fast for one row);
  everything else is precomputed by `train_and_export.py` for snappy loading.
- The corridor daily budget (240 block-minutes) and crew capacity (90
  units/day) in `train_and_export.py` are demo assumptions, not sourced
  from real COA/TMS capacity data — tune them if you want the schedule to
  look different.
- This is a plain HTML/JS frontend, not the React+TypeScript dashboard from
  the pitch — it's meant to get real model output on screen quickly. Ask if
  you'd like a React/Vite version instead; the API underneath doesn't need
  to change.
